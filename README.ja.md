# Conference Ops Engine

**技術カンファレンスの企画・運営を支援する、再利用可能なAIワークフロー基盤。**

[木村慎一 / fourn9](https://github.com/fourn9) がAIコーディングアシスタントを活用して開発したプロジェクトの公開ケーススタディです。[English](README.md)

登壇候補の調査、招待文の準備、スポンサー対応、イベント後の分析などを、繰り返し使えるスキルとワークフローに整理しました。共通手順をエンジンに集約し、各イベントの進捗や業務データを別のリポジトリで管理する構成が設計の中心です。

このリポジトリには、過去の非公開プロジェクトの設計説明と、公開用に新規作成した小さな再現デモを収録しています。デモは当時のソースコードそのものではありません。

## 試す

Python 3.9以上。外部ライブラリ・APIキー・ネット接続は不要です。

```bash
git clone https://github.com/fourn9/conference-ops-engine.git
cd conference-ops-engine
python3 demo/research.py
python3 -m unittest discover -s tests -v
```

架空の候補4件を評価し、「人のレビュー待ち1件・保留2件・不採用1件」を出力します。実イベントの成果数値ではありません。[出力例](examples/research-review.md)

## 元プロジェクトで実装したもの

- 調査・文面作成・スポンサー対応・レポート作成をまとめたスキルとコマンド。
- テーマや対象層ごとに並行調査し、構造化した結果を検証するワークフロー。
- 出典・本人の経験・テーマ適合性を確認し、不明なものは保留にする仕組み。
- ヒアリングの記録から対象者・テーマ選定の根拠をたどれる設計。
- 共通エンジンを指定バージョンで各イベントに取り込み、改善をレビュー経由で戻す運用。

## 公開デモの範囲

デモは入力された架空の検証結果を評価します。Webでの実調査やLLM呼び出し、外部への送信は行いません。人物・イベント・インタビューは架空で、URLも例示用です。重複した候補は根拠を消さずに保留し、最終採用は人の判断として分離しています。

イベント単位の業務・記憶管理は、[Conference Ops Workspace](https://github.com/fourn9/conference-ops-workspace) にまとめています。
