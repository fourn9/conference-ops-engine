# /record-learning

セッション中の発見を領域worklog `decisions-log.md` に保存する。
（v2 の `LEARNINGS.md` 相当。本リポでは既存の `decisions-log.md` を学習ログ層として使う。二重ログを作らない。）

## いつ呼ぶか

- フェーズ実行中に「これは次回も役立つ」と思える発見があった
- ユーザーの選好・規約・環境について学んだ（→ 人物像なら `USER.md` を優先）
- 既存スキル・方法論では捕捉できていなかった文脈を発見した

## いつ呼ばないか（anti-noise）

- 単なる作業ログ（「ファイルを編集した」「テストを走らせた」）
- PR#・Issue#・commit SHA を含む取引的記録
- 推測・仮説（事実として書かない。どうしても残すなら `[推測]` を明記）
- ユーザーへのネガティブな評価

## 実行手順

1. `decisions-log.md` を Read で読む
2. 今日の日付ヘッダ `## YYYY-MM-DD` が無ければ作り、その下に既存スタイルで追記する：
   - 1エントリ 1〜3行、箇条書き
   - イベント名があれば `[conference]` 等のプレフィックスを付ける
   - 「やったこと／気付き・tips／次回への申し送り」のいずれかに該当する形で書く
3. 追記後、ユーザーに「以下を `decisions-log.md` に追記しました」と差分を提示
4. **declarative で書いたか確認** — 「X を好む」「Y の傾向」など観察形。命令形（「常に X せよ」）になっていたら書き直す

## 引数

引数なしで呼べる（agent が文脈から内容を決める）。
ユーザーから明示的に内容を指定された場合はそれを優先する。

## 関連

- `CLAUDE.md` §自律的学習プロトコル（書き込みトリガ／declarative）
- 同じ気付きを 3 回書いていることに気づいたら `/draft-adr` を提案
- 反復可能な手順としてスキル化できそうなら `/draft-skill` を提案
- `decisions-log.md` のエントリが重い方針判断に育ったら `/draft-adr` で ADR に昇格
