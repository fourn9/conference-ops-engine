# 日本語ビジネスメール作成

## パラメータ

| パラメータ | 説明 | 例 |
|---|---|---|
| RECIPIENT | 相手の名前・所属・関係性 | 「[担当者名]様 / 株式会社ABC / スポンサー候補・初回接触」 |
| PURPOSE | 用件の要旨 | 「[イベント名] のスポンサー提案後フォロー」 |
| PHASE | 関係性のフェーズ | `first-contact` / `ongoing` / `post-event` / `internal` |
| TONE | 温度感（任意） | `formal` / `warm` / `casual`（省略時は関係性から判断） |
| CONTEXT | 前回のやり取り・特記事項（任意） | 「先週提案資料を送付済み、返信なし」 |

未指定の場合は実行前に確認する。

---

## トーン判断軸

TONE が未指定の場合、RECIPIENT と PHASE から以下で判断：

| 相手 × フェーズ | トーン | 備考 |
|---|---|---|
| 海外登壇者（英語） | フォーマル + 簡潔 | 日本式前置き不要 |
| 国内登壇者・初回 | 丁寧 + 具体的接点あり | 賛辞は1行以内に |
| 国内登壇者・既存関係 | 自然 + 温度感を保つ | 過度な敬語を抑える |
| スポンサー候補・初回 | プロフェッショナル + 価値提示 | 自社宣伝より相手のベネフィット |
| スポンサー・既存 | 信頼ベース + カジュアル寄り | 「いつもありがとうございます」で十分 |
| 参加者・一斉送信 | 親しみやすく + 情報明確 | 行動を促す1つのCTAに絞る |
| 社内（メール） | 簡潔 + 依頼事項明確 | Slack で済む話はメールにしない |

## 件名の設計

件名は開封率を左右する。以下の基準で設計する：

**良い件名の条件：**
- 用件が一読でわかる（「ご連絡」「お世話になっております」で始めない）
- 相手に関係する固有名詞を含む（イベント名・プラン名）
- アクションが必要な場合はそれを示す（「ご確認のお願い」「日程調整のご相談」）

✅ 良い例：
- 「[イベント名] スポンサープランのご提案」
- 「登壇資料提出期限のご確認（5/31）」
- 「[要返信] [イベント名] 登壇テーマのすり合わせ」

❌ 悪い例：
- 「ご連絡」
- 「先日の件について」
- 「よろしくお願いいたします」

## 避けるべき表現

### AI っぽい定型句（避ける）
- 「お忙しいところ恐縮ですが」を毎回冒頭に置く
- 「何卒よろしくお願い申し上げます」の連発
- 「ご査収のほどよろしくお願いいたします」
- 「ご多忙のこととは存じますが」

### 二重敬語（避ける）
- ❌「お伺いさせていただきます」→ ✅「伺います」
- ❌「ご拝読いただけますと」→ ✅「お読みいただけますと」
- ❌「お送りさせていただきました」→ ✅「お送りしました」
- ❌「ご確認いただけましたでしょうか」→ ✅「ご確認いただけましたか」

### 冗長な依頼（避ける）
- ❌「ご検討いただけますと幸いに存じます」
- ✅「ご検討ください」または「ご検討いただけますでしょうか」

## 推奨される本文構成

```
件名：[具体的な内容を含む簡潔な件名]

[相手の名前・敬称]

お世話になっております。
[主催組織]の[自分の名前]です。

[1段落目：用件の要旨を最初に。「○○についてご相談があります」から始める]

[2段落目：背景・詳細・数字があれば]

[3段落目：相手にしてほしいこと（明確に1つに絞る）]

[締め：軽めに。「よろしくお願いいたします」で十分]

──────
[署名]
```

本文は400-600字を目安（長すぎる場合は要点をリスト化 + 詳細は別添）。

## フォローアップのタイミング判断

| 状況 | 対応 |
|---|---|
| 送信後5営業日返信なし（スポンサー提案後） | 件名はそのままで「ご検討状況のご確認」として1行送信 |
| 送信後3営業日返信なし（期限が近い案件） | 締切日を明記して再度確認 |
| 「検討中」のまま2週間以上 | 「何か不明点はございますか」と入口を変える |
| 1ヶ月以上音沙汰なし | Slackや電話など別チャネルへ切り替えを提案 |

---

## チャネル選択の判断

メールを選ぶ前に確認する：

| 用件 | 推奨チャネル |
|---|---|
| 社内の簡単な確認・報告 | Slack |
| 社外への正式な提案・契約関連 | メール |
| 社外への初回コンタクト | メール（温度感に応じてX DM も） |
| 緊急・当日対応 | 電話 or Slack（社内）/ メール + 電話（社外） |
| イベント前日以降の登壇者対応 | メール + 担当者直通 |

## イベント固有の情報

開催日・期限・確定事項は `conference/event.md` を参照し、未確定事項は未確定と示す。

## 出力手順

1. RECIPIENT・PURPOSE・PHASE・CONTEXT を確認（未指定は質問）
2. トーンを決定
3. 件名と本文の案を生成
4. ユーザーに提示して確認を取る
5. 修正は指摘箇所のみ修正（全体を書き直さない）
6. 送信はユーザーが行う（このスキルは下書き作成まで）

---

## 安全装置

- 送信は行わない
- Gmail Draft への保存は、ユーザーの明示的な指示がある場合のみ
- 金額・契約条件の数字は人間が確認する
- 送信前に「添付資料の有無」をユーザーに確認する

接続先・保存先の共通設定は `docs/configuration.md` を参照。既にユーザーが明示した条件は再確認せず、その範囲で進める。
