# イベントコピーライティング

## パラメータ

| パラメータ | 説明 | 例 |
|---|---|---|
| TYPE | 文面の種類 | `press-release` / `sns-post` / `reminder` / `thanks` / `lp-copy` / `announcement` |
| EVENT | 対象イベント | 「[イベント名]（[開催日]）」 |
| AUDIENCE | 対象者 | `participants`（参加者）/ `sponsors`（スポンサー）/ `speakers`（登壇者）/ `public`（一般） |
| PHASE | イベントとの時間的関係 | `pre-event` / `day-of` / `post-event` |
| CONTEXT | 追加情報（任意） | 「[確認済みの参加者数]」「初開催」「海外登壇者あり」 |

未指定の場合は実行前に確認する。

---

## TYPE別の作成指針

### press-release（プレスリリース）

**スポンサー募集プレスリリース（PHASE: pre-event）**
構成：
1. タイトル：イベント名・開催概要・スポンサー募集開始を含む
2. リード文：開催意義・対象読者・規模感（1〜2文）
3. イベント概要：日時・会場・対象者・参加予定人数
4. スポンサーメリット：具体的なリーチと価値（数字を含む）
5. プラン概要：プラン名と主要特典（金額は記載しない）
6. 申込・問い合わせ先

判断基準：
- 「なぜ今このイベントが必要か」を1段落で説明できるか確認
- 競合イベントとの差別化を1行で言えるか確認
- 書けない場合は `methodology/conference-planning-framework.md` で企画骨子を先に整理する

**事後プレスリリース（PHASE: post-event）**
構成：
1. タイトル：開催報告・参加者数・主要ハイライト
2. リード文：開催結果サマリー
3. 数値実績：参加者数・セッション数・満足度など
4. 印象的なセッションや登壇者（2〜3名）
5. 来場者の声（匿名化した代表コメント2〜3件）
6. 次回開催予告（あれば）
7. 問い合わせ先

### sns-post（X/SNS投稿）

**登壇者告知投稿**
- 媒体とアカウントの投稿上限内に収める
- 登壇者名・所属・セッションテーマ・イベントURL・ハッシュタグ
- 「なぜこの人の話が面白いか」を一言で添える
- 登壇者本人がRTしやすい書き方（名指し・セッションテーマ明記）

例：
```
【登壇決定🎉】@handle さん（株式会社ABC / CTO）が
「[セッションタイトル]」についてお話しいただきます。

[セッション内容を1行で]

▶ 詳細・申込: [URL]
#[ハッシュタグ]
```

**開催直前告知**
- 締切・残席・開催日を前面に
- 申込リンクは必ず含める
- 「まだ間に合う」「残り〇席」など行動を促す言葉

**当日ライブ投稿**
- セッション開始時・印象的な発言・写真投稿
- 登壇者・参加者がRTしたくなる具体的な内容（抽象的なまとめは避ける）
- ハッシュタグを必ず含める

### reminder（リマインドメール）

**参加者向け前日リマインド**
必須項目：
- 開催日時・会場住所（地図リンク）
- 受付開始時刻・入場方法
- 持ち物・服装（あれば）
- 当日の問い合わせ先（電話番号）
- タイムテーブル（またはリンク）

トーン：親しみやすく、情報は箇条書きで明確に。

**スポンサー向け前日リマインド**
必須項目：
- 搬入・設営時間
- ブース位置（レイアウト図リンク）
- 当日担当者の連絡先
- 駐車場・搬入口の案内
- 回収物の最終確認（未提出があれば明記）

**登壇者向け前日リマインド**
必須項目：
- 入り時間・控室場所
- 登壇時刻・セッション時間・質疑応答の有無
- 機材確認の時間
- スライド提出状況の確認
- 当日担当者名と連絡先

---

### thanks（お礼文）

**参加者向けお礼メール（PHASE: post-event）**
構成：
1. 参加へのお礼（具体的な数字を含む：「〇〇名のご参加」）
2. イベントのハイライト（印象的なセッション1〜2個）
3. アンケートへの協力依頼（リンク付き）
4. アーカイブ・資料公開の予告（または案内）
5. 次回イベントの予告（あれば）

**登壇者向けお礼メール（PHASE: post-event）**
構成：
1. 登壇へのお礼（そのセッションの具体的な反響を含む）
2. 参加者からの反応・コメント（ポジティブなもの2〜3件。匿名で）
3. アーカイブ・資料公開の案内・確認
4. 次回への期待（関係継続の意思表示）

判断基準：
- 「そのセッションだけに言及した内容」を1行書けるか確認
- 書けない場合は `post-event-survey-report` のセッション評価を先に確認する

**スポンサー向けお礼メール（PHASE: post-event）**
→ `japanese-business-email` スキルと `post-event-survey-report` の出力を組み合わせて作成

### lp-copy（LP・申込ページの文章）

**申込ページ主要コピー**
- キャッチコピー：「誰が」「何を得られるか」を10字以内で
- サブコピー：ターゲット読者と課題感を1〜2文で
- CTAボタン：「参加申込はこちら」より「〇月〇日 無料で参加する」のように具体的に

**サンクスページ・サンクスメール**
- 申込完了への感謝
- 当日までに知っておくべきこと（会場、時間）
- 次のアクション（SNSフォロー、仲間への紹介）

**キャンセルメール**
- キャンセル完了の確認
- 次回イベントへの案内
- アーカイブ配信があれば案内

---

### announcement（各種告知・案内文）

**懇親会案内メール**
- 開催日時・場所・形式（立食 / 着席）
- 参加費（無料なら明記）
- 申込方法・締切
- ドレスコード（あれば）

**来場者事前案内メール**
- イベント概要（日時・場所）
- タイムテーブルリンク
- 事前に読んでおくと良い資料（あれば）
- 当日の連絡先

## イベントのトーン基準

| 媒体 | トーン | 注意点 |
|---|---|---|
| プレスリリース | フォーマル、数字重視 | 「〜と思われます」を避け断定形で |
| X投稿 | 親しみやすく、具体的 | 抽象的な「素晴らしい」を避ける |
| メール（参加者） | 親しみやすく、情報明確 | 1メール1アクション |
| メール（スポンサー） | プロフェッショナル | 金額・条件は別途確認 |
| LP | 簡潔、行動喚起 | 「〜していただけますと幸いです」は使わない |

---

## よくある失敗パターン

| 失敗 | 原因 | 対策 |
|---|---|---|
| 読まれないプレスリリース | 「開催のお知らせ」だけのタイトル | イベントの数字・ターゲット・差別化を含める |
| RTされないSNS投稿 | 登壇者の何がすごいかが伝わらない | 「なぜこの人」を1文で書く |
| 前日リマインドが役に立たない | 必要な情報（住所・連絡先）が抜けている | チェックリストで必須項目を確認 |
| お礼メールが定型文に見える | そのセッション固有の言及がない | アンケートコメントを1件以上引用する |

---

## 安全装置

- 送信は行わない（文面作成まで）
- 参加者・登壇者・スポンサーの個人名を含む場合は、公開前に確認を取る
- 数値（参加者数・満足度）はユーザーが提供したデータのみ使用。推測で書かない
- スポンサー名・登壇者名の掲載には、事前の掲載承諾確認が必要（OKかユーザーに確認）

## 関連スキル

- スポンサー関連メール → `japanese-business-email` と組み合わせて使う
- 登壇者お礼の文面ネタ → `post-event-survey-report` のセッション別評価を参照
- 登壇者告知投稿の情報 → `diarize-person` で事前に情報収集

接続先・保存先の共通設定は `docs/configuration.md` を参照。既にユーザーが明示した条件は再確認せず、その範囲で進める。
