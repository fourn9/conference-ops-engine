# スポンサー対応オペレーション

## パラメータ

| パラメータ | 説明 | 例 |
|---|---|---|
| COMPANY | 企業名 | 「株式会社ABC」 |
| PLAN | スポンサープラン | `Diamond` / `Platinum` / `Gold` / `Silver` / `Bronze` |
| PHASE | 現在のフェーズ | `planning` / `negotiation` / `onboarding` / `ops` / `post` |
| CONTEXT | 特記事項（任意） | 「昨年も協賛、担当者変更あり」「登壇枠あり」 |

未指定の場合は実行前に確認する。

---

## フェーズ別タスクチェックリスト

### PHASE: planning（営業計画）
*時期目安: イベント7〜8ヶ月前（4〜5月）*

**事前確認（local/vault）**
- [ ] `01-research/companies/` で過去の協賛・接点ノートを確認
- [ ] `Memory.md`（領域全体・イベント単独）で関連事項を確認

- [ ] スポンサー枠数・プラン確定（運営責任者確認）
- [ ] 販売プラン作成・確認
- [ ] 営業リスト作成（新規・既存を区別）
- [ ] 営業資料作成・POと運営責任者確認
- [ ] 申込フォーム作成
- [ ] プレスリリース検討（集客・スポンサー計画と連動）

### PHASE: negotiation（営業・商談）
*時期目安: 7ヶ月前〜確定まで*

**事前確認（候補企業ごと）**
- [ ] local/vault `01-research/companies/{企業名}.md` で既存ノートを確認
- [ ] 既存なし → claude.aiでリサーチ実行 → `00-inbox/` 投入
- [ ] inbox整理（`status: reviewed` に更新、`01-research/companies/` 配下に昇格）

- [ ] スポンサー候補企業への声かけ
- [ ] 商談実施
- [ ] 反社チェック（申込後に必ず実施）
- [ ] スポンサー確定・運営責任者に報告

### PHASE: onboarding（受注後の初期設定）
*時期目安: 確定後1週間以内*

- [ ] 企業ごとのSlackチャネル作成
  - 命名規則: `#sponsor-[企業名略称]-[イベント略称]`
- [ ] Slackチャネルへの招待（先方担当者）
- [ ] 招待確認・参加リマインド（未参加なら1週間後に再送）
- [ ] Slackチャネル内にQA BOT設定
- [ ] Slackチャネルにて今後のスケジュール案内（打ち合わせ日程含む）
- [ ] 収益計算シートに記載
- [ ] 経理担当者に請求書作成依頼
- [ ] 請求書Wチェック・送付
- [ ] 売上管理シートに記載

### PHASE: ops（当日に向けた運営対応）
*時期目安: 3〜1ヶ月前*

**回収物（登壇枠なしスポンサー）**
- [ ] ロゴ回収フォーム作成・送付
- [ ] 企業ロゴ回収完了確認
- [ ] 幕間動画回収（対象プランのみ）
- [ ] ツール/サービス情報フォーム作成・回収

**登壇枠があるスポンサーの場合（追加）**
- [ ] 登壇内容すり合わせのMTG設定
- [ ] 登壇内容擦り合わせ
  - MTG後の合意内容サマリとお礼メール下書きは `sponsor-mtg-followup` スキルを使う
- [ ] 登壇者フォーム作成・情報回収
- [ ] タイトル・アブストラクト回収・FIX
- [ ] 登壇資料提出締切の案内
- [ ] 登壇環境アンケート回収

**マニュアル類**
- [ ] スポンサーマニュアル作成・Wチェック・送付
- [ ] 登壇者マニュアル作成・Wチェック・送付（登壇枠あり）
- [ ] 各社ブース運営スタッフ登録回収
- [ ] 当日運営マニュアル送付（更新項目確認・認識合わせ）

**LP・プレスキット**
- [ ] スポンサーにLP公開連絡・プレスキット送信

**懇親会**
- [ ] 懇親会参加者回収（対象プランのみ）

**前日対応**
- [ ] 前日リマインドテキスト作成（`event-copywriting` スキルを使う）
- [ ] 前日リマインド送付

### PHASE: post（イベント後）
*時期目安: イベント翌日〜2週間以内*

- [ ] スポンサーアンケートフォーム作成・送付
- [ ] アンケート回収
- [ ] リードデータ作成（参加者データから）
- [ ] リードデータWチェック
- [ ] スポンサーにリードデータ配布
- [ ] スポンサーへお礼メール（お礼＋参加者コメント＋写真）
  → `japanese-business-email` スキルを使う
- [ ] 開催レポートのスポンサー配布
- [ ] （トラブルあれば）MTGセット

## 判断基準

### 追加募集が必要かの判断
- 目標枠数に達していない場合、イベント4ヶ月前に判断
- タイムテーブル再検討・追加プレスリリースの検討と連動

### Slackリマインドの判断
- 参加確認が取れない場合：招待から1週間後に1回リマインド
- それ以降の強引な追跡は関係を損なうため避ける

### モニター申込がある場合
- 請求月の確認 → 収益計算シート更新 → 経理担当者にモニター請求書作成依頼 → Wチェック・送付

## Notion管理

各スポンサー企業のNotionページ（`notion-page-format` スキルのスポンサー管理ページ）を以下のタイミングで更新：
- 商談履歴：商談のたびに追記
- ステータス：フェーズが変わるたびに更新
- 回収物状況：ロゴ・動画・情報の回収完了時

---

## 安全装置

- 金額・契約条件の数字は人間が確認する（請求書の送付前に必ずWチェック）
- リードデータの配布前に個人情報の取り扱い確認を行う
- Slack送信・メール送信は下書き作成まで。送信はユーザーが行う
- 反社チェック未完了の企業に対して、マニュアル等の機密性の高い資料を送付しない

## local/vault 連携

- 各企業のVaultノート（`01-research/companies/{企業名}.md`、テンプレート: `templates/sponsor-profile-template.md`）にステータス・商談履歴を記録
- フロントマター `sponsor_status` を以下のフェーズと同期：

| フェーズ | sponsor_status |
|---|---|
| negotiation | `proposal-sent` / `negotiating` |
| onboarding | `contracted` |
| post | `closed` |

- 正本はNotion、Vaultは「リサーチ知識として残す」位置づけ（重複管理）

## 関連スキル

- メール文面作成 → `japanese-business-email`（PHASE: ongoing または post-event）
- 前日リマインド・お礼文面 → `event-copywriting`
- Notionページ更新 → `notion-page-format`（スポンサー管理ページ）
- アンケート集計・レポート → `post-event-survey-report`

接続先・保存先の共通設定は `docs/configuration.md` を参照。既にユーザーが明示した条件は再確認せず、その範囲で進める。
