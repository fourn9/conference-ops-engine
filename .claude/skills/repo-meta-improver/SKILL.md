# Conference Ops Meta Improver

## このスキルは特別重要

リポジトリの設定ファイル（CLAUDE.md, AGENTS.md, SKILL.md）は、
このプロジェクトでの Claude の挙動を決定づけるファイル。
これらの変更は慎重に行う必要がある。

**`disable-model-invocation: true` 設定済み。**
ユーザーが `/repo-meta-improver` で明示的に呼び出した時のみ動作する。

## 使用タイミング

- 月1回程度の定期メンテナンス
- 「最近 Claude の挙動がイマイチ」と感じた時
- 新しいイベント・新しいタスクパターンが定着してきた時
- **`post-event-survey-report` の Step 6 でスキル改善提案が生成された時**（最優先）

## 改善提案の入力元

このスキルへの改善提案は2つのルートから来る：

| ルート | トリガー | 特徴 |
|---|---|---|
| **A. 自律型**（通常の月次メンテ） | `/repo-meta-improver` の手動呼び出し | 会話傾向・ファイル構造から自分で発見する |
| **B. フィードバック型**（学習ループ） | `post-event-survey-report` Step 6 からの提案 | アンケートデータに基づく具体的なdiff案が届く |

**ルートBの場合**、Step 1-2の現状把握は省略してよい。
届いた提案を「ルートAの提案3以降」として追記し、Step 4（ユーザーレビュー）から開始する。

## 実行手順

### 1. 現状把握

以下を確認：
- 最近の会話傾向（過去会話検索で直近2-4週間）
- 既存ファイル一覧（CLAUDE.md, AGENTS.md, .claude/skills/*/SKILL.md）
- 各ファイルの最終更新日（git log）

### 2. 改善ポイントの分析

以下の観点で分析：

#### CLAUDE.md / AGENTS.md について
- 同じ説明・修正を何度も繰り返していないか
- 不要になった記述（終了したイベント情報など）
- 矛盾する記述
- 300行を超えていないか（長すぎる場合は要圧縮）
- スキルに切り出すべき手順が紛れていないか

#### スキルについて
- description が曖昧で発動しにくくなっていないか
- 似たスキルが重複していないか
- 使われていないスキルはないか
- 新規に作るべきスキルパターンが見えていないか

#### 全体の構造
- AGENTS.md と CLAUDE.md の役割分担が崩れていないか
- 安全装置が緩んでいないか
- ツール固有の設定がプロジェクト共通設定に漏れていないか

### 3. 提案の作成

以下のフォーマットで提案：

```markdown
# 改善提案 - [日付]

## 観察された傾向
[直近の会話から見えたパターン]

## 提案する変更

### 提案1：[変更タイトル]

**対象ファイル**：CLAUDE.md
**理由**：[なぜこの変更が必要か]
**影響範囲**：[どのスキル・どの作業に影響するか]

**変更内容（diff）**：
\`\`\`diff
- 古い記述
+ 新しい記述
\`\`\`

**コミットメッセージ案**：
refactor(claude-md): 〜

---

### 提案2：[変更タイトル]
...
```

### 4. ユーザーレビューを待つ

提案を提示したら、ユーザーが以下を判断：
- 採用する
- 修正したうえで採用する
- 却下する
- 追加情報を求める

### 5. 採用された変更を適用

ユーザーの明示的な承認を得たもののみ：
- ファイルを編集
- `git-commit` スキルを呼び出してコミット
- push はしない

## 安全装置（重要）

このスキルは特に強い安全装置を持つ：

### 絶対にやらないこと

1. **直接ファイルを書き換えない**
   - 必ず提案 → 確認 → 適用の流れ

2. **複数の変更を一度に適用しない**
   - 1提案 = 1コミットを基本とする

3. **大規模な構造変更を勝手に提案しない**
   - 「CLAUDE.md を全面書き直し」「全スキルを再構成」のような大変更は
     ユーザーから明示的に依頼されない限り提案しない

4. **既存の安全装置を緩めない**
   - 「disable-model-invocation を外す」「確認を省略する」のような
     安全装置を弱める変更は提案しない

5. **機密情報を新規に書き込まない**
   - 改善過程で得た情報（具体的な金額、個人連絡先など）は
     設定ファイルに書き込まない

### 必ず行うこと

1. **すべての提案に「却下」の選択肢を明示**
2. **影響範囲を必ず説明**
3. **diff 形式で変更を可視化**
4. **コミットメッセージ案を併記**

## 自己言及的な改善

このスキル自身（repo-meta-improver/SKILL.md）の改善も対象になりうる。
その場合は特に慎重に：
- 安全装置の弱体化につながる変更は提案しない
- 変更後にスキル自体が機能するか動作確認を提案する

## 関連

- 実際のコミットは `git-commit` スキルを呼び出す
- リポジトリ全体のポリシーは AGENTS.md の「このリポジトリの管理ポリシー」を参照

接続先・保存先の共通設定は `docs/configuration.md` を参照。既にユーザーが明示した条件は再確認せず、その範囲で進める。
