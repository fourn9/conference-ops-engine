# Git Commit（安全装置あり）

## このスキルの重要な注意

**`disable-model-invocation: true` 設定済み。**
Claude が「コミットすべきタイミングだ」と判断して自動実行することはない。
ユーザーが `/git-commit` と明示的に呼び出した時のみ動作する。

## 使用タイミング

ユーザーが `/git-commit` を呼び出した時。

## 実行手順

### 1. 状態確認

以下を順番に実行：
```bash
git status
git diff --staged   # ステージされている変更
git diff            # ステージされていない変更
```

### 2. 差分の解釈

差分を見て：
- 変更の意図を要約
- 変更ファイルのカテゴリ分類（CLAUDE.md / SKILL.md / docs / その他）
- 破壊的変更の有無を確認

### 3. コミットメッセージ案の作成

Conventional Commits 形式で：

```
<type>(<scope>): <subject>

<body>

<footer（必要なら）>
```

#### type の選び方

| type | 用途 |
|---|---|
| feat | 新スキル追加・新機能追加 |
| fix | 誤情報修正・バグ修正 |
| docs | ドキュメント更新 |
| refactor | スキル・ドキュメントの整理 |
| chore | 運用上の変更（gitignore等） |

#### scope の選び方
- `skills`：スキル全般の変更
- `skills/<name>`：特定スキルの変更
- `claude-md`：CLAUDE.md の変更
- `agents-md`：AGENTS.md の変更
- `docs`：docs/ 配下の変更

#### subject のルール
- 72文字以内
- 命令形（「追加」「修正」「整理」）
- 末尾にピリオドなし
- 日本語可

### 4. ユーザーへの提示

以下を提示してユーザーの確認を待つ：

```
## 変更の概要
[1-2行]

## 変更ファイル
- 追加：[ファイル数]
- 変更：[ファイル数]
- 削除：[ファイル数]

## コミットメッセージ案

\`\`\`
feat(skills/japanese-business-email): スポンサーフォローアップテンプレを追加

過去のメール文例から共通パターンを抽出し、スポンサーフォローアップの
標準テンプレートを作成。フェーズ別（提案後・契約中・終了後）の3パターン。

関連 Issue: #XX
\`\`\`

このメッセージで commit してよろしいですか？
（OK / 修正したい場合は具体的に指示）
```

### 5. コミット実行

ユーザーが「OK」「commit して」など明示的に承認した後のみ実行：

```bash
git add <該当ファイル>
git commit -m "<メッセージ>"
```

## 安全装置

このスキルでは以下を**絶対に行わない**：

1. **ユーザーの確認なしでコミットしない**
   - 必ずメッセージ案を提示し、明示的な承認を得る

2. **`git push` は実行しない**
   - リモートへの反映は別の判断が必要
   - ユーザーが手動で push するか、別のスキル / コマンドで明示的に実行

3. **大量のファイルを一度にコミットしない**
   - 5ファイル以上の変更がある場合は、論理的に分割するか確認
   - 関連性の薄い変更は別コミットに分ける提案をする

4. **`.gitignore` に書かれているはずのファイルが含まれていたら警告**
   - `.env` `node_modules` `secrets/` 等
   - 機密情報が含まれていないか念のため確認

5. **強制プッシュ・履歴改変はしない**
   - `git commit --amend`、`git rebase`、`git push --force` は実行しない
   - これらが必要な場合はユーザーに任せる

## エラー時の挙動

- マージコンフリクト中は自動解決を試みない
- `git status` でわからない状態なら、ユーザーに状況を報告して指示を仰ぐ
