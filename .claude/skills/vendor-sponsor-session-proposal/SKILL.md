# ベンダースポンサー登壇企画書の作成

## 原則

1. **企画は3点交差で作る。** 聴衆の課題、企業が当事者として語れること、企業のマーケティング目的を満たす。
2. **根拠の強さを明示する。** 過去実績、聴衆データ、参加者調査、ニュース性の順に扱い、仮説は仮説と書く。
3. **製品紹介を設計判断へ昇格させる。** どのレイヤーで解くか、責務や統制をどう分けるかを主題にする。
4. **企画書はターゲット目線、根拠は運営用控えに置く。**
5. **競合差別化は名指しせず、設計論点として扱う。**

## 手順

1. 営業担当、商談記録、前年資料、イベントの聴衆リサーチ、直近の一次情報、公開顧客事例を調査する。
2. 共同登壇による実例案と、スポンサー単独の設計論案の2案を設計する。選択の議論になるよう、語り手・狙う層・実行上の条件を分ける。
3. 各案に、現在地、課題、提供できる具体的な実例または判断基準、視聴ターゲットを記す。
4. 運営用控えには根拠マップ、重複チェック、未確認事項を残す。強さを「実績／データ／公開情報／仮説」で明示する。
5. 企画書を更新後に読み戻し、既存セクションを壊していないことを確認する。

## チェックリスト

- [ ] 2案とも聴衆課題・当事者性・マーケ整合の根拠がある
- [ ] 2案とも設計判断が主題になっている
- [ ] 直近の一次情報を確認した
- [ ] 他セッションと切り口が重複しない
- [ ] 未確認事項と仮説を企画書本文に混ぜていない

接続先・保存先の共通設定は `docs/configuration.md` を参照。既にユーザーが明示した条件は再確認せず、その範囲で進める。
