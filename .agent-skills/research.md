# Research スキル（Conference向け）

## 目的

local/vault に蓄積されたリサーチノートを読み込み、カンファレンス運営の意思決定（登壇者選定・スポンサー打診・テーマ設計・会場選定）に必要な構造化情報を作る。

## 実行手順

### Step 1: 検索範囲の確定

依頼内容を以下のカテゴリに分類してから読み込みを開始する：

| カテゴリ | 主な参照先 | 主なユースケース |
|---------|----------|---------------|
| 人物 | `01-research/people/` | 登壇候補選定、専門家ヒアリング |
| 企業 | `01-research/companies/` | スポンサー打診、パートナー選定 |
| テーマ | `01-research/themes/` | 基調テーマ設計、CFP方針 |
| 会場 | `01-research/venues/` | 会場選定、運営知見 |

複数カテゴリにまたがる場合は全部見る。

### Step 2: Obsidian MCP で読み込み

優先順位：
1. **`01-research/{category}/`** を Obsidian MCP の `list_directory` / `search_files` で検索（整理済み・信頼度高）
2. **`00-inbox/`** を補助確認（`status: raw` のノートが残っていれば参照、ただし信頼度は低め）
3. **フォールバック**：Obsidian MCP が使えない場合のみ Google Drive MCP の `search_files` でキーワード検索

各ノートのフロントマターを必ず確認する：
- `status` が `raw` の場合は「未整理情報」として扱う
- `updated` が古い場合は鮮度に注意（半年以上前なら追加調査が必要）
- `tags` で関連ノートを横展開

### Step 3: 軸ごとの情報抽出

カテゴリ別に以下の軸で抽出する。

#### 人物（people）
- **専門領域**：技術スタック・ドメイン
- **過去登壇歴**：どのイベントで何を話したか
- **最近の発信**：直近半年のSNS・ブログ・登壇内容
- **フィット感**：当該カンファレンスとの親和性
- **接点**：既存のつながり・経由ルート
- **想定リスク**：忙しさ・直前のキャンセル傾向・他社イベント優先度

#### 企業（companies）
- **業種・規模・採用ニーズ**：スポンサー価値の根拠
- **過去の協賛実績**：他カンファレンスへの協賛履歴
- **キーパーソン**：意思決定者・予算保有者
- **フィット感**：採用ターゲット層と参加者層の重なり
- **提案ロジック**：訴求ポイント・想定プラン

#### テーマ（themes）
- **業界の話題性**：技術トレンド・規制動向・市場変化
- **競合カンファレンス**：他で扱っているテーマとの差別化
- **登壇候補との接続**：このテーマで話せる人物の有無
- **参加者の関心**：過去アンケート・SNS反応

#### 会場（venues）
- **キャパ・設備**：参加人数・配信機材・電源
- **アクセス**：駅近・空港アクセス
- **コスト**：賃料・付帯費用
- **過去利用実績**：他イベントでの評価

### Step 4: 統合サマリーの作成

読んだ内容を以下のフォーマットで出力する：

```markdown
## リサーチサマリー（YYYY-MM-DD時点）

### 対象カテゴリ
{people|companies|themes|venues}

### 主要な発見
- ...

### カテゴリ別の整理
（該当カテゴリの軸で整理）

### 推奨アクション
- 短期（このセッション中に動かせるもの）：
- 中期（1-2週以内に確認すべきもの）：

### 未解決の問い（リサーチギャップ）
- 不明な点1
- 不明な点2

### 出典ノート
- [[ファイル名1]]
- [[ファイル名2]]
```

### Step 5: ギャップの特定とinbox昇格判定

以下に答えられない場合は「リサーチギャップ」として明示する：

- **人物**：本人にコンタクトできるルートはあるか？登壇可否を判断できる材料はそろっているか？
- **企業**：意思決定者にリーチできるか？協賛価値を伝えるロジックは成立するか？
- **テーマ**：そのテーマで語れる登壇者は3名以上確保できるか？
- **会場**：開催希望時期に押さえられるか？

`00-inbox/` 内に未昇格のノートが残っている場合：
- `status: raw` → `reviewed` に更新
- 適切な `01-research/{category}/` 配下に移動
- ファイル名を `YYYY-MM-DD_テーマ.md` に整える

## Exit Criteria

- 対象カテゴリのノートを全て読み終えた
- カテゴリ別の軸が埋まっている
- リサーチギャップが明示されている
- 推奨アクションが「次にやること」として書ける状態になっている
- 関連する `Memory.md`（領域全体・イベント単独）の `次にやること` を更新した
