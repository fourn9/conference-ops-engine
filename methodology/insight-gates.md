# インサイト・ゲート（n=1 ヒアリング必須）

カンファ企画で「エンジニアの生の声（n=1 ヒアリング）」を入れずに、**土台**と**最終決定**を確定しない。
対象者へのヒアリングを、**2つのロックイン地点だけ**に門として置く（中間段階には置かない）。

## 必須成果物

`conference/01-planning/hearing-insights.md`（テンプレ同梱）。
最低限：誰に聞いたか / 課題・ペイン / 知りたいこと / 生の声（引用） / 日付。
各エントリに `INS-xxx` の ID を振り、決定はこの ID を `insight_ref` として参照する。

> n=1 でよい。網羅性より「実在する当事者の声」を優先する。

## Gate 1 — コアターゲット＋近接領域の確定前

- **対象の決定**：コアターゲット（規模×目的×職種のペルソナ）と、その**近接領域**（隣接テーマ・領域）。
- **条件**：
  1. `hearing-insights.md` が存在し、必須項目が埋まっている。
  2. 各コアターゲット／近接領域に、由来する `insight_ref`（ヒアリング項目 ID）を1つ以上示せる。
- **満たさないとき**：その決定を**確定しない**（保留 or 追加ヒアリング）。憶測・Web のみ由来は不可。

## Gate 2 — テーマ＋登壇者の最終決定前

- **対象の決定**：セッションテーマの最終確定と、登壇者の最終確定（`methodology/conference-planning-framework.md` の探索前ゲートと併用）。
- **条件**：各テーマ／登壇者が、**Gate 1 を通ったコアターゲット／近接領域 → ヒアリング由来インサイト** に辿れる（`insight_ref`）。
- **満たさないとき**：そのテーマ／登壇者は**採用しない**。

## やらないこと

- Matrix 作成途中などの**中間段階に門は置かない**。確定の2点だけ。
- ヒアリングを重い必須プロセスにしない。少数の生の声で十分。

適用する企画手順は `methodology/conference-planning-framework.md` を参照。
